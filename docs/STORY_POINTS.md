# Jira Story Point 입력 기준 공유안

이 문서는 Backend 저장소에서 사용하는 공유안입니다. 다른 파트의 예시는 추정 기준을 이해하기 위한 참고입니다.

Story Point(SP)는 작업의 **작업량·복잡도·불확실성**을 함께 고려한 상대적인 크기입니다.
1 SP를 1시간이나 1일로 환산하지 않으며, 개인의 실력·기여도를 평가하는 점수로 사용하지 않습니다.

## 사용할 점수: 1 · 2 · 3 · 5 · 8 · 13

- **1 SP**: 범위가 매우 작고 방법이 분명한 작업
- **2 SP**: 기존 방식을 활용할 수 있고 확인할 경우가 적은 작업
- **3 SP**: 하나의 기능 구현과 정상·오류 상황 검증이 필요한 작업
- **5 SP**: 여러 처리 흐름이나 데이터 변경이 연결되는 작업
- **8 SP**: 외부 연동·동시성·복구 등 확인할 요소가 많은 작업
- **13 SP 이상**: 작업 분할 또는 사전 조사를 먼저 검토

위 기준은 팀 적용 제안입니다. API 1개, 화면 1개마다 고정 점수를 붙이지 않고 실제 완료 범위로 판단합니다.

## 우리 프로젝트 예시

아이 프로필 조회와 이메일 PIN 재설정은 모두 API 작업이지만,
PIN 재설정에는 이메일 인증·권한 무효화·오류·경합 테스트가 포함되므로 더 큰 작업일 수 있습니다.

AI 연동도 호출 성공뿐 아니라 시간 초과·실패 응답·재시도 여부까지 고려합니다.
FE·BE·AI 모두 익숙한 완료 작업을 기준 사례로 정해 비교해 주세요.

실제 개발 업무인 Story/Task 단위에서 한 번만 산정하는 방안을 제안합니다.
Epic이나 하위 작업을 별도로 더해 같은 작업을 중복 집계하지 않습니다.

## 주의할 점

- 외부 답변 대기는 의존성·차단 사유로 기록합니다. 대기 날짜를 그대로 SP로 더하지 않습니다.
- 범위가 바뀌면 공유 후 분할·재추정을 검토합니다.
- 오래 걸렸다는 이유만으로 완료 후 점수를 올리지 않습니다.
- 완료 조건을 충족한 업무만 완료량에 포함합니다.
- 파트마다 따로 정한 점수로 생산성을 비교하지 않습니다.

입력 이유 예시:

> 5 SP 제안 — 이메일 재인증, PIN 변경, 기존 보호자 권한 무효화와 오류·경합 테스트 포함
